Este documento consolida y unifica el contenido de la presentación interactiva del proyecto para alinearlo con los **10 capítulos de la memoria académica**.

Sigue la **Regla de Oro de la Narrativa de Presentaciones**:
```
[Portada] ──> [Presentación] ──> [Dolor Empresa] ──> [Requisitos] ──> [Diseño Técnico] ──> [Contexto IA] ──> [Uso de IA] ──> [Desarrollo] ──> [Manuales] ──> [Resultados] ──> [Conclusiones]
```

Cada diapositiva está estructurada con:
1. **Mensaje Clave y Título:** La idea central que debe retener la audiencia.

3. **Notas Completas del Ponente:** El discurso hablado detallado, transiciones entre diapositivas y pautas de tono.

* **Mensaje Clave:** La resiliencia del proyecto ante fallos de ingeniería reales, solucionando la exposición de credenciales y depurando bugs lógicos silenciosos de parsing de JSON.
* **Título de la Diapositiva:**  
  `CAPÍTULO 7: CASOS DE ESTUDIO Y ERRORES`  
  `Lecciones de Seguridad, Optimización de Consultas y Bugs Silenciosos`
* **Contenido en Pantalla:**
  * **Exposición de API Key (Caso de Seguridad):**
    * *Error:* Clave de API de Anthropic hardcodeada en el cliente web.
    * *Solución:* Implementación de Vercel Serverless Functions como proxy seguro para ocultar keys en el backend.
  * **Optimización de Consultas (Caso de Rendimiento):**
    * *Error:* El catálogo se colgaba al consultar categorías de 400.000 productos.
    * *Solución:* Refactorizar `getCategorias()` a 1 consulta única optimizada y optimización O(1) de marcas.
  * **Validator de Fichas (Caso de Depuración Silenciosa):**
    * *Error:* El callback del validador de respuestas del chatbot devolvía array en lugar de boolean, descartando silenciosamente datos válidos.
    * *Solución:* Code review completo del flujo de datos y corrección de Object.assign.
* **Notas del Ponente:**
  > *"Finalmente, el Capítulo 7 expone los errores y aprendizajes técnicos reales que forjaron mi experiencia. El primer mes expusimos la API key en el frontend; lo solucionamos creando una función serverless en Vercel. También nos enfrentamos a problemas de rendimiento en la base de datos debido a consultas pesadas, que resolvimos reduciendo el lookup de marcas a orden constante O(1). Por último, depuramos un bug silencioso en el validador JSON del chatbot que descartaba datos sin emitir logs de error, reafirmando la lección de que no hay que confiar a ciegas y siempre se debe auditar el flujo completo de los datos."*
