02 / Capítulo 1

Presentación del Proyecto y Objetivos

Concepto y Propuesta

Proyecto PFC: Aplicación web (SPA) con 8 herramientas para técnicos del sector de distribución eléctrica.

Diferenciador: Metodología de desarrollo asistida por IA (humano-IA) con lecciones documentadas para otros estudiantes.

Objetivos Técnicos

⚡ OE1 (Funcionalidad): 7 módulos (catálogo, picking, incidencias, KPIs, presupuestos, competencias y chatbot).

🤖 OE2 (Metodología): Catalogar 15+ herramientas IA y workflow CLI.

🔌 OE3/5 (Calidad/Coste): React 19 + Supabase PostgreSQL con coste de 0.00€.

02B / Capítulo 1

Tecnologías, Métricas y Ámbito

Métricas y Stack Core

💻 Core Stack: React 19 + Vite 7 + Supabase + Vercel.

📊 Métricas: 4.689 productos indexados y 7 herramientas SPA.

🧪 Testing: 425 tests (270 Vitest / 155 Playwright E2E).

💰 Presupuesto: 0.00€ coste de licencias e infraestructura.

Ámbito del Proyecto

✅ Incluye: Suite de 7 herramientas funcionales, scraping de catálogo real, chatbot SONEX y legado didáctico docente.

❌ Excluye: App móvil nativa, integración directa con el SAP de Sonepar y pasarelas de pago real.

03 / Capítulo 2

Fugas de Productividad en Sonepar

Contexto y Prácticas

Estudio de campo en Sonepar Ibérica (distribución B2B de material eléctrico profesional con 500+ empleados). La observación directa durante las prácticas reveló cuellos de botella severos en los procesos logísticos y de soporte técnico.

5 Ineficiencias de Campo

🔍 1. Fichas Técnicas: Búsqueda lenta en catálogos y PDFs dispersos.

⚠️ 2. Compatibilidad: Dudas constantes de equivalencias de marcas.

📊 3. Presupuestos: Cotizaciones manuales y lentas en Excel.

🎓 4. Formación: Control descentralizado y opaco de competencias.

📝 5. Incidencias: Registro en papel sin histórico ni trazabilidad.

08C / Capítulo 7

Aprendizajes y Errores de Ingeniería

Casos de Estudio

🔑 API Key Expuesta: Clave de Anthropic expuesta en frontend. Corregido mediante Vercel Serverless Functions como proxy seguro.

📦 Base de Datos: Bloqueo por límites de escritura de Firestore Spark. Corregido migrando a Supabase PostgreSQL.

Bugs Silenciosos y Aciertos

🐛 Bug de validación JSON: Validador que retornaba array en lugar de boolean, descartando respuestas. Detectado por code review del flujo de datos.

💡 Aciertos: Modularidad a base de Custom Hooks y uso de CSS Modules (cero runtime overhead).
