# Actividades propuestas

## Actividad 1 — Detectar una alucinación

**Objetivo:** comprobar que una respuesta convincente no es necesariamente correcta.

1. Pedir a un LLM una explicación técnica con una fuente.
2. Identificar qué afirmaciones requieren verificación.
3. Contrastar al menos una con documentación oficial.
4. Entregar una tabla: afirmación / evidencia / veredicto.

## Actividad 2 — Prompt con contrato

Transformar “hazme una app” en una instrucción que incluya:

- objetivo;
- alcance;
- exclusiones;
- entradas/salidas;
- criterios de aceptación;
- pruebas;
- condiciones de parada.

Evaluar si el agente añadió trabajo no solicitado.

## Actividad 3 — Revisión de diff

Sobre un repositorio de práctica:

1. pedir una corrección pequeña;
2. revisar el diff;
3. clasificar cada cambio como necesario, opcional o fuera de alcance;
4. revertir lo que no corresponda;
5. documentar el motivo.

## Actividad 4 — Evidencia de testing

Ejecutar build y pruebas y entregar:

- commit probado;
- comandos;
- códigos de salida;
- resumen de tests;
- un fallo investigado, si existe;
- limitaciones de la evidencia.

## Actividad 5 — Fuente oficial antes de usar IA

Elegir una cuestión de normativa o seguridad eléctrica. El alumno debe localizar primero la fuente oficial y después usar IA solo para resumirla. Se compara el resumen con el texto fuente y se señalan desviaciones.

## Actividad 6 — Mini proyecto

En grupos de 2-3:

- definir una necesidad técnica pequeña;
- construir un prototipo;
- usar Git con commits comprensibles;
- documentar interacciones relevantes con IA;
- incluir al menos una validación automática;
- defender qué está verificado y qué queda pendiente.

## Criterio común

No se puntúa “usar más IA”. Se puntúa **resolver mejor el problema y demostrarlo**.
