# PFC Stabilization Closeout Design

## Goal
Close `chatgpt/pfc-hardening-20260818` as a genuinely stable integration candidate by making the static-analysis/toolchain/dependency/test gates reproducible and green on one final HEAD, without expanding into product features or Supabase-dependent work.

## Scope

### In scope
1. Review and resolve the current ESLint warnings. Prefer code fixes for genuine dead code or hook-contract defects. Use a narrow, documented local suppression only when the existing behavior is intentional and a refactor would materially increase regression risk.
2. Add a real TypeScript `typecheck` gate using the existing `tsconfig.json`; add TypeScript as a direct dev dependency and wire the command into CI/deploy verification.
3. Declare the Node runtime contract used by CI and Vercel-compatible builds.
4. Audit current dependency state and security advisories. Update compatible patch/minor dependencies through the lockfile; do not perform major migrations unless required to resolve a security or correctness blocker.
5. Refresh Browserslist/caniuse-lite data as part of the compatible dependency refresh.
6. Obtain a fresh successful GitHub Actions run including Playwright Chromium E2E on the final HEAD.
7. Re-run final lint, typecheck, Vitest, production build and E2E and review the branch diff against `main`.

### Explicitly out of scope
- Supabase RLS audit or database migrations while the production project is paused.
- Centralized analytics/admin authorization requiring the live Supabase project.
- Vite 8 or other major-version migrations unless a blocking vulnerability makes them necessary.
- React architecture refactors whose only purpose is satisfying a lint preference.
- Product functionality or visual redesign unrelated to stabilization.

## Design decisions
- Treat warnings as evidence, not as a numeric target. The desired final state is zero warnings; if a warning cannot be removed safely without behavioral redesign, suppress only that exact line/rule with a reason and retain tests covering the behavior.
- `no-unused-vars` returns to blocking severity once existing dead-code warnings are fixed.
- Hook dependency warnings are fixed at the responsible layer. Do not add dependencies mechanically if doing so changes effect frequency or creates loops.
- TypeScript remains `strict: false` for this closeout. The new gate verifies the existing TS contract; enabling `strict` is a separate migration.
- Dependency updates are limited to versions compatible with existing semver ranges unless a direct package declaration must be adjusted to make the toolchain explicit. The package lock is regenerated by npm in CI, never edited by hand.
- Node 20 is the stabilization runtime contract because the CI already uses Node 20.
- E2E must run against Playwright's configured `webServer`; no manually pre-started Vite server is accepted as proof.

## Closure criteria
The branch is ready for integration only when all of the following are true on one HEAD:
- ESLint: 0 errors, 0 warnings (or only explicitly justified local suppressions that do not emit warnings).
- TypeScript: `tsc --noEmit` passes.
- Vitest: full suite passes.
- Production Vite build passes.
- GitHub Actions Playwright Chromium E2E passes.
- `npm audit` has no unresolved high/critical vulnerability; lower-severity findings are documented if not safely fixable without a major migration.
- Compatible dependency refresh is committed and lockfile is reproducible under `npm ci`.
- `main` has not advanced relative to the branch merge-base, or any advance has been reconciled before integration.
- Final diff contains no Supabase-live changes, merge, force-push, or unrelated product work.
